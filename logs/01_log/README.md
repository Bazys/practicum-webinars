# Примеры: пакет `log`

Базовые возможности классического логгера Go.

## Запуск

```bash
cd examples
go run ./01_log/01_basic.go
go run ./01_log/02_logger_flags.go
go run ./01_log/03_output.go
```

> Каждый файл — отдельный `package main` со своей `func main()`.
> Запускайте по одному.

## Что в каждом файле

### `01_basic.go` — Print / Fatal / Panic
- `Println`, `Printf` — обычный вывод
- `recover()` перехватывает `Panic`
- Закомментированный `log.Fatal` — попробуйте раскомментировать,
  увидите, что deferred-функция НЕ выполнится (программа выйдет с кодом 1)

### `02_logger_flags.go` — `log.New` и флаги
- Создание собственного логгера через `log.New(writer, prefix, flags)`
- Демонстрация всех флагов форматирования на отдельном `bytes.Buffer`
- `Lmsgprefix` — куда кладётся префикс
- Метод `Output(calldepth, ...)` для управления источником строки

### `03_output.go` — `io.MultiWriter` и лог в файл
- `os.OpenFile` в режиме append (`O_APPEND|O_CREATE|O_WRONLY`)
- `io.MultiWriter(os.Stdout, file)` — дублирование вывода
- `log.SetOutput` — переключение стандартного логгера
- После запуска создаётся `demo.log` с теми же сообщениями

## Подводные камни

- **`log.Fatal` не выполнит `defer`.** Используйте только при инициализации,
  никогда — в обработчиках HTTP-запросов.
- **`io.MultiWriter` останавливается на первой ошибке.** Если один из writer'ов
  сломается, остальные не получат данные.
- **Глобальный логгер** — удобно для скриптов, но тяжело тестировать.
  В больших проектах создавайте свой `*log.Logger` через `log.New`.
